# FILE CONTRACTS — contracts of the durable artefacts

Guard against decorative artefacts (spec §15). Each durable artefact is contracted here by: category (normative / derived / operational / evidence / ephemeral), responsibility, writer and update trigger, freshness and forbidden contents. An artefact that no longer satisfies its usefulness test is deleted or re-evaluated (spec §59). Revision of 2026-11-06.

## Deterministic tooling (`tools/pws_workspace/`)

Factoring contract: **`scan.py` is the sole implementation of the product/source facts** (axes §44), **`profiles.py` the sole owner of the profiles, licence axes, consistency rules and v1 derivation** (shared by scan, guard, menu, licensing, migration), **`validation.inspect_validation` the sole owner of the mechanical validation**, **`config.py` the sole writer of `pws.config.json`**. `standard.py`, `guard.py`, `tv_mode.py` (delegates writing to `config.py`), `i18n.py` (fr/en catalogue), `menu.py` (tree), `banner.py` (banners: fixed "PWS" constant of the `/pws` menu, without adaptation; adaptive PINE-WORKSPACE variants of the `banner` subcommand, width measured at each display, plain text as fallback; data of the structured outputs, never a prefix), `migration.py` (idempotent steps, backup, rollback), `maintenance.py` (allowlist cleanup, archive import), `tooling.py` (PineTS lifecycle), `github.py` (export), `licensing.py` (templates), `distribution.py` (build; the marker declares the known migration steps and the official repository), `update.py` (guided update path: dated search for releases, verification of the packages — provenance, hash, confined extraction, manifest —, plan bound by hash, orchestration of `upgrade` then `migrate` by the new code, rollback information; writes only `.claude/runtime/pws-update/` and temporary folders outside the installation), `release.py` (publication artefacts of a version: archive, SHA-256, `RELEASE.json`, notes; publishes nothing), `version.py` (single source of the number and of the official repository) each own their domain; `session.py` and `doctor.py` AGGREGATE and never re-derive a fact. `core.py`: shared primitives (paths, physical boundary — symlinked `scripts/` never read, scans without following symlinks, `runtime_tree_is_real` —, safe identifiers, hash, atomic JSON, `file_lock` locks, read-only git tolerant of the absence of Git); narrow boundary exception: `list_user_skill_names()` (names from `~/.claude/skills`).

**Concurrent writes**: `pws.config.json` (`pws.config.json.lock` lock), validation init/promotion (`scripts/<slug>/.pws-validation.lock`), cleanup (`.claude/runtime/maintenance/cleanup.lock`, non-blocking: a concurrent run is ignored), archive import and deletion of the imported folder (`.claude/runtime/maintenance/archives.lock`: a concurrent operation is refused), session import records (`.claude/runtime/session/imports.lock`: re-read under lock, never overwritten by another session), core upgrade and data migrations (shared lock `.claude/runtime/pws-mutation.lock`: a concurrent operation is refused, never interleaved; uniquely named backups created exclusively, copies and restorations verified by hash, paths physically confined). The `*.lock` files are gitignored and must NEVER be deleted.

**Mutating subcommands**: `init`, `config set`, `tv-mode <mode>`, `github destination-*` (configuration; invalidation of the plans and setting aside of a clean clone under `.claude/runtime/github-export/`); `standard-index` (INDEX); `import-register` (ephemeral); `migrate --apply|--rollback` (prior backup under `.claude/runtime/migration-backup/`); `pinets verify --record` (PROVENANCE, first time only), `pinets install|rollback` (engine, PROVENANCE, STALE calibrations, restore point); `github export-plan|fetch|publish` (staging and clones under `.claude/runtime/github-export/`; publication only with `--yes`); `maintenance cleanup --execute|archives-import|archives-remove-source`; `license write|set-fields` (files under the product root, on the holder's grouped confirmation) and `license confirm` (confirmed facts in the manifest); `build-distribution` (outside the workspace); `upgrade`, `update apply`, `update guide --stage apply`, `pinets guide --stage apply` (engine, PROVENANCE, calibrations and their results under `.claude/runtime/pinets-recalibration/`), `build-release`; `update guide --stage prepare` and `pinets guide --stage prepare` write only a plan file under `.claude/runtime/` and download outside the workspace. Everything else is read-only. The destructive, publication, installation and update-application operations (`init`, `upgrade`, `migrate --apply|--rollback`, `maintenance cleanup --execute|archives-import|archives-remove-source`, `license write|set-fields|confirm`, `pinets install|rollback|verify --record`, `pinets guide --stage apply`, `github publish|fetch|destination-remove`, `update apply`, `update guide --stage apply`, `git push`, the modifying forms of `git remote` and `git tag`, `gh release create|edit|upload|delete|delete-asset`, `gh repo create`, `gh auth login`) are subject to an `ask` rule of the project; since 2.2.0, local commits, local builds, update searches and downloads without application have none (see the `.claude/settings.json` row) (`.claude/settings.json`, no `allow` rule covering them; verified by `tools/tests/test_settings_rules.py`): the confirmation comes in addition to the checks of the commands, it never replaces them. The tests (`tools/tests/`) are the execution evidence: the full suite must pass before any health declaration.

## Idempotence, migration and re-execution (spec §55)

Any re-execution: detect what exists first; NEVER overwrite `DECISIONS.md`, `validation/`, research runs, a specific `PRODUCT.md`, the skills without diff/review, `settings.local.json`, the approvals or `pws.config.json`. `migrate --plan` is read-only; `--apply` backs up before writing and logs; `--rollback <stamp>` restores byte for byte. `upgrade --plan` is read-only; `--apply` backs up, refuses locally modified core files without `--overwrite-local`, keeps the locally mutable files (`.pws-new`), restores automatically in case of failure; `--rollback` refuses as long as later data migrations are applied (`MIGRATION.md`). `install.py` refuses to overwrite an existing installation or a non-empty folder and redirects to `upgrade`; `build-distribution` refuses a target that is not empty or a previous PWS build.

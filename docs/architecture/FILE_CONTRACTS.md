# FILE CONTRACTS — contrats des artefacts durables

Garde contre les artefacts décoratifs (spec §15). Chaque artefact durable est contracté ici par : catégorie (normatif / dérivé / opérationnel / preuve / éphémère), responsabilité, writer et déclencheur de mise à jour, fraîcheur et contenus interdits. Un artefact qui ne satisfait plus son test d'utilité est supprimé ou réévalué (spec §59). Révision du 2026-11-06.

## Tooling déterministe (`tools/pws_workspace/`)

Contrat de factorisation : **`scan.py` est l'unique implémentation des faits produits/sources** (axes §44), **`profiles.py` l'unique propriétaire des profils, axes de licence, cohérences et dérivation v1** (partagé par scan, guard, menu, licensing, migration), **`validation.inspect_validation` l'unique propriétaire de la validation mécanique**, **`config.py` l'unique écrivain de `pws.config.json`**. `standard.py`, `guard.py`, `tv_mode.py` (délègue l'écriture à `config.py`), `i18n.py` (catalogue fr/en), `menu.py` (arborescence), `banner.py` (bannières : constante fixe « Pine-WS » du menu `/pws`, sans adaptation ; variantes adaptatives PINE-WORKSPACE de la sous-commande `banner`, largeur mesurée à chaque affichage, texte brut en repli ; donnée des sorties structurées, jamais un préfixe), `migration.py` (étapes idempotentes, sauvegarde, retour), `maintenance.py` (entretien liste blanche, import d'archives), `tooling.py` (cycle de vie PineTS), `github.py` (export), `licensing.py` (modèles), `distribution.py` (construction ; le marqueur déclare les étapes de migration connues et le dépôt officiel), `update.py` (parcours guidé de mise à jour : recherche datée des releases, vérification des paquets — provenance, empreinte, extraction confinée, manifeste —, plan lié par empreinte, orchestration de `upgrade` puis `migrate` par le nouveau code, information de retour arrière ; écrit seulement `.claude/runtime/pws-update/` et des dossiers temporaires hors installation), `release.py` (artefacts de publication d'une version : archive, SHA-256, `RELEASE.json`, notes ; ne publie rien), `version.py` (source unique du numéro et du dépôt officiel) possèdent chacun leur domaine ; `session.py` et `doctor.py` AGRÈGENT et ne re-dérivent jamais un fait. `core.py` : primitives partagées (chemins, frontière physique — `scripts/` symlinké jamais lu, balayages sans suivi de symlink, `runtime_tree_is_real` —, identifiants sûrs, hash, JSON atomique, verrous `file_lock`, git read-only tolérant à l'absence de Git) ; exception de frontière étroite : `list_user_skill_names()` (noms de `~/.claude/skills`).

**Écritures concurrentes** : `pws.config.json` (verrou `pws.config.json.lock`), init/promotion de validation (`scripts/<slug>/.pws-validation.lock`), entretien (`.claude/runtime/maintenance/cleanup.lock`, non bloquant : une exécution concurrente est ignorée), import d'archives et suppression du dossier importé (`.claude/runtime/maintenance/archives.lock` : une opération concurrente est refusée), enregistrements d'import de session (`.claude/runtime/session/imports.lock` : relus sous verrou, jamais écrasés par une autre session), mise à niveau du cœur et migrations de données (verrou partagé `.claude/runtime/pws-mutation.lock` : une opération concurrente est refusée, jamais entrelacée ; sauvegardes à nom unique créées exclusivement, copies et restaurations vérifiées par empreinte, chemins confinés physiquement). Les fichiers `*.lock` sont gitignorés et ne doivent JAMAIS être supprimés.

**Sous-commandes mutantes** : `init`, `config set`, `tv-mode <mode>`, `github destination-*` (configuration ; invalidation des plans et mise de côté d'un clone propre sous `.claude/runtime/github-export/`) ; `standard-index` (INDEX) ; `import-register` (éphémère) ; `migrate --apply|--rollback` (sauvegarde préalable sous `.claude/runtime/migration-backup/`) ; `pinets verify --record` (PROVENANCE, première fois seulement), `pinets install|rollback` (moteur, PROVENANCE, calibrations STALE, point de retour) ; `github export-plan|fetch|publish` (staging et clones sous `.claude/runtime/github-export/` ; publication seulement avec `--yes`) ; `maintenance cleanup --execute|archives-import|archives-remove-source` ; `license write|set-fields` (fichiers sous le product root, sur confirmation groupée du titulaire) et `license confirm` (faits confirmés dans le manifeste) ; `build-distribution` (hors du workspace) ; `upgrade`, `update apply`, `build-release`. Tout le reste est read-only. Les opérations destructrices ou de publication (`init`, `build-distribution`, `build-release`, `upgrade`, `migrate --apply|--rollback`, `maintenance cleanup --execute|archives-import|archives-remove-source`, `license write|set-fields|confirm`, `pinets install|rollback|verify --record`, `github publish|fetch|destination-remove`, `update check|fetch|apply`, `git commit|push|remote|tag`, `gh release`, `gh repo create`) sont soumises à une règle `ask` du projet (`.claude/settings.json`, aucune règle `allow` qui les couvre ; vérifié par `tools/tests/test_settings_rules.py`) : la confirmation s'ajoute aux contrôles des commandes, elle ne les remplace jamais. Les tests (`tools/tests/`) sont la preuve d'exécution : la suite complète doit passer avant toute déclaration de santé.

## Idempotence, migration et réexécution (spec §55)

Toute réexécution : détecter l'existant d'abord ; ne JAMAIS écraser `DECISIONS.md`, `validation/`, research runs, un `PRODUCT.md` spécifique, les skills sans diff/revue, `settings.local.json`, les approvals ni `pws.config.json`. `migrate --plan` est en lecture seule ; `--apply` sauvegarde avant d'écrire et journalise ; `--rollback <stamp>` restaure octet pour octet. `upgrade --plan` est en lecture seule ; `--apply` sauvegarde, refuse les fichiers de cœur modifiés localement sans `--overwrite-local`, conserve les fichiers localement mutables (`.pws-new`), restaure automatiquement en cas d'échec ; `--rollback` refuse tant que des migrations de données postérieures sont appliquées (`MIGRATION.md`). `install.py` refuse d'écraser une installation existante ou un dossier non vide et renvoie vers `upgrade` ; `build-distribution` refuse une cible qui n'est pas vide ou une construction PWS précédente.

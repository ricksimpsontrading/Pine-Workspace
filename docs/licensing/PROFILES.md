# Licence profiles — FREE / PRIVATE / COMMERCIAL

*Text templates (English) are in `templates/`; their reuse permission is in `TEMPLATE_PERMISSION.md`.*

## Principle

A profile is a **starting configuration**, never a quality rule nor an imposed publication mode: free or paid, the design, the documentation, the tutorial and the validation criteria are the same (master standard §5). It never forces the existing licence of an imported script (see "Existing licence of an imported script"). The axes remain separate in the `SCRIPT.json` manifest (schema 3) and are adjusted individually:

| Axis | Values | Role |
|---|---|---|
| `profile` | FREE, PRIVATE, COMMERCIAL | usage profile (defaults) |
| `license.id` / `license.grant` | CC-BY-NC-SA-4.0 / cc; PROPRIETARY / none, free-use, eula; existing licence of an imported script / license | licence and permissions |
| `license.origin` / `license.status` | absent or `profile` (licence of a profile); `imported` with `confirmed` or `to-analyse` | existing licence of an imported script, kept (see below) |
| `license.source_visibility` | public, closed | is the code published or delivered? |
| `license.access` | free, paid, restricted | access conditions |
| `license.terms_ref` / `license.terms_url` | relative path in the product / https URL | declared legal reference of the product (rendered terms; hosted URL, for example on the author's GitHub repository) |
| `publication.state` | unpublished, published, null (unknown) | is the script published on TradingView? |
| `publication.privacy` | public, private, null | privacy of the TradingView publication (community feed or not) |
| `publication.mode` | open, protected, invite-only, null | TradingView script mode (source visible; source hidden; access by invitation) |

The three publication dimensions are independent: a private publication can be open, protected or invite-only. An unknown value remains `null` and is flagged (`PUBLICATION_STATE_UNKNOWN`, `PUBLICATION_INCOMPLETE`), never inferred. Nothing is derived automatically; consistency is checked across axes: `mode = open` requires a `public` source; a library is always `public` in `open` mode; `paid` access expects a `public` publication in `invite-only` mode (TradingView rule consulted on 2026-11-06: only a public invite-only script may be paid; the sale of a private script, or of access to it, is forbidden) — otherwise a warning before publication. The only value derived for display: the "FREE with closed source" variant (FREE profile under a proprietary `free-use` licence).

**Documents follow the licence axes, not the profile name.** The licence and the permission (`license.id`, `license.grant`) determine the documents that are served, can be generated and are checked: CC BY-NC-SA 4.0 → CC header; `free-use` → proprietary header and free-use grant; `none` → proprietary header and notice (optional particular permission); `eula` → proprietary header and EULA. When the profile describes a regime other than its axes (for example a FREE profile under an EULA or without a permission, a PRIVATE or FREE profile with paid access, a COMMERCIAL profile without an EULA), the scanner flags it (`PROFILE_AXES_DIVERGENCE`, warning): it is up to the holder to confirm which one is right.

Starting defaults:

| Profile | Licence | Source | Access | Publication (state / privacy / mode) | Reference text |
|---|---|---|---|---|---|
| **FREE** | CC BY-NC-SA 4.0 (attribution, non-commercial, share-alike) | public | free | unpublished / public / open | `templates/HEADER_FREE_CC_BY_NC_SA.txt` |
| **FREE with closed source** (FREE profile, adjusted axes) | proprietary + free-use grant (`free-use`) | closed | free | unpublished / public / protected | `templates/FREE_USE_GRANT_CLOSED_SOURCE.md` |
| **PRIVATE** | proprietary, all rights reserved, no general permission | closed | restricted | unpublished / null / null (privacy and mode unknown until set) | `templates/NOTICE_PROPRIETARY_SHORT.md` |
| **COMMERCIAL** | proprietary + configurable EULA | closed | paid | unpublished / public / invite-only | `templates/EULA_COMMERCIAL_TEMPLATE.md` |

Points of attention:

- **CC BY-NC-SA 4.0**: Creative Commons does not recommend its licences for software; the choice is deliberate for a published script whose author sets the terms, and it does not replace TradingView's own rules (publication rules, moderation), which apply in addition.
- **PRIVATE** in PWS is a usage profile (personal, internal, limited sharing, particular permissions possible). It is neither a private TradingView publication (`publication.privacy`) nor a private GitHub repository (export destination). A PRIVATE product may remain unpublished, or be published privately with a defined mode.
- **COMMERCIAL**: the rights of use and of access are distinct from intellectual property; the purchase assigns no ownership. The EULA remains a **draft** as long as the indispensable fields (`release/eula-fields.json`) are not filled in: the rendered text then carries an explicit "DRAFT — not for publication" banner, it is never exported to GitHub, and `pine-release` flags it; this does not block development. PWS never invents a legal identity, an address, a jurisdiction, a refund policy or commercial terms, and introduces neither a universal "no refund" clause nor a removal of statutory warranties.
- **Declared legal reference**: `terms_url` is the only product-specific URL that the guard admits in a source (in a comment, exact match) — never a whole domain nor "all GitHub URLs". Declared without attached terms (`terms_ref` null), it is flagged. No URL is invented for an existing product. A third-party licence URL is never declared as `terms_url`: it falls under the notice rule below.
- **Third-party notices and attributions**: they are kept verbatim; a notice is never removed to satisfy the guard. The guard admits, through a targeted rule and only in a comment, recognized licence URLs: licence texts of the licence bodies (Creative Commons, public-domain tools including CC0, MPL, Apache, GNU, OSI, SPDX), over `https://` as over `http://`, and the `LICENSE` / `COPYING` / `NOTICE` file of the original repository on a known code host when the comment is a licence notice. No general URL exemption: a promotional URL remains blocking, as does any URL in a text displayed to the user. A header that carries the declared licence and another licence mention is flagged (warning: third-party notice to keep or contradiction to analyse).
- **Attached terms**: `license confirm --terms-ref` attaches only the current and complete rendering of the terms document of the product's axes (EULA, free-use grant or notice), written by `license write`; a draft, a copy that is no longer current or any other file (manifest, decisions…) is refused. The status of the terms is read on the attached document itself: it becomes a draft again if this document is no longer the current rendering of the recorded information (field modified, year or identity changed), until a new generation.
- **Bounded writes**: `license write` writes only a document of the product's axes, directly under `release/` (default name or new name; `.md` for documents, `.txt` for headers), never through a symbolic link, and replaces an existing file only at the default destination of this document or at its attached copy. `license confirm` refuses a value that would make the manifest invalid (for example an `open` mode for a closed source) and never writes into an already broken manifest; `confirm` and `set-fields` run under a product lock, without loss between two commands in close succession. Only the holder's fields of `release/eula-fields.json` feed the rendering: identity, years and URLs always come from the manifest and the configuration (any other key stays in the file, ignored and flagged).
- **Existing licence of an imported script** (holder's decision of 2026-11-13, audit finding C-19; compatible extension of schema 3, `schema_version` unchanged, no existing manifest modified or migrated). The profiles remain the configurations proposed to new projects; they never force the licence of an imported script, which keeps its text, its notices, its attributions and its licence. Four notions remain distinct: usage profile, licence (exact `license.id`), source visibility, publication (state, privacy, mode).
  - **Record**: `license.origin` = `imported`, `license.status` = `confirmed`, `license.id` = **exact** SPDX identifier confirmed by the holder, `license.grant` = `license` (rights defined by the licence itself; `cc` for CC-BY-NC-SA-4.0). Closed list: MPL-2.0 (default header of the Pine Editor), MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, GPL-2.0-only, GPL-2.0-or-later, GPL-3.0-only, GPL-3.0-or-later, LGPL-2.1-only, LGPL-2.1-or-later, LGPL-3.0-only, LGPL-3.0-or-later, AGPL-3.0-only, AGPL-3.0-or-later, and CC-BY-NC-SA-4.0 (for example a script by a third-party author under this licence).
  - **Exactness**: "only" and "or later" are never conflated — a notice "either version 3 of the License, or (at your option) any later version" gives `-or-later`, a notice "version 3" alone `-only`, any other wording is to analyse: several versions or a choice between versions ("version 2 or 3", "v2 or v3", "either version 2 of the License, or (at your option) version 3", SPDX expression `GPL-2.0-only OR GPL-3.0-only`) never give a single `-only` or `-or-later` identifier, nor does a "later" mention without that clause. The deprecated and ambiguous SPDX identifiers (`GPL-2.0`, `GPL-3.0`, `LGPL-2.1`, `LGPL-3.0`, `AGPL-3.0`, and their "+" forms `GPL-2.0+`, `GPL-3.0+`, `LGPL-2.1+`, `LGPL-3.0+`, `AGPL-3.0+`) are never recorded and remain to analyse, on an `SPDX-License-Identifier` line as in the text of the notice ("Licensed under GPL-3.0"). `MIT` designates the Expat text: an X11 notice, or the "MIT License" mention alone (an ambiguous term according to the FSF), is to analyse.
  - **"To analyse"**: custom, ambiguous or unrecognized licence, Creative Commons variant other than BY-NC-SA 4.0, several licences or contradictory mentions → `license.status` = `to-analyse`, `license.id` = null. The state is explicit (`LICENSE_TO_ANALYSE` warning, never a silent broken manifest): it does not prevent routine work, but publication preparation and the export wait until the holder records the exact licence (`license confirm --license-id`).
  - **Proposal, never evidence**: reading the header (`license detect`, `license overview`) proposes an identifier; it is never legal evidence and nothing is recorded without the holder's confirmation.
  - **Possible conflicts** (copyleft licence — MPL, GPL, LGPL, AGPL — with a closed source; copyleft licence, CC BY-NC-SA included, with a `protected` or `invite-only` mode or paid access — for CC BY-NC-SA, its NonCommercial clause; permissive licence whose notice must accompany the work): warnings to analyse (`IMPORTED_LICENSE_CONFLICT`), never an automatic block presented as a legal conclusion. Only the mechanical rule of CC BY-NC-SA 4.0 takes precedence: a closed source under this licence, imported or not, makes the manifest broken (`LICENSE_VISIBILITY_MISMATCH`: `public` source required, as for the FREE profile) and is never additionally presented as a point to analyse.
  - **Guard**: it checks that the existing notice is still present and consistent with `license.id` (a missing notice, or one that establishes another licence of the same family, blocks — the record is corrected with the holder, never the notice; a notice that does not establish the recorded identifier exactly — several versions, deprecated identifier, ambiguous wording — gives a warning, never a block nor a silent acceptance). The notice is read in the header and in the initial comment block that follows the `//@version` directive, up to the first line of code, where its authors may have placed it: it is never moved. It requires neither the CC header, nor "All Rights Reserved", nor a © line of the configured holder (the original authors remain cited); the targeted rule for licence URLs in notices remains the one described above. A licence to analyse leaves the header template unverifiable.
  - **Licence guided path**: no PWS terms document is imposed (neither a template header, nor an EULA, notice or grant); `overview` and `status` display "existing licence kept" (or "to analyse").
  - **Original legal documents** (holder's request of 2026-11-14; same compatible extension of schema 3, existing manifests unchanged): the files that accompany the licence in the script's original distribution — licence text, `NOTICE`, attributions — remain as they are in the product, at the root or directly under `release/` (names `LICENSE`, `LICENCE`, `COPYING`, `COPYRIGHT`, `NOTICE`, `PATENTS`, `AUTHORS`, `CREDITS`, `ATTRIBUTION`, `CONTRIBUTORS`, `THIRD_PARTY_NOTICES` and their variants: `LICENSE.md`, `LICENSE-MIT`, `COPYING.LESSER`, `NOTICE.txt`…), or under `LICENSES/` (REUSE layout: `LICENSES/MIT.txt`). The holder declares them (`license.documents`, through `license confirm --license-document <path>` repeated; `--no-license-documents` when no separate document accompanies the script; `--clear license_documents` to return to "not declared"); the GitHub export then sends them **verbatim** (same name — `LICENSES/<name>` kept —, same bytes, same encoding, same language; Git must not modify them at commit time), never replaced by a PWS template nor compared with a template. A legal-document name never suffices to include a file; none is set aside silently either, wherever it is in the product (except `research/`, `validation/`, `tests/`): as long as the documents are not declared, a file found with a legal-document name is not declared or cannot be declared where it is (misplaced, folder, link — the holder moves it), or a declared document is missing, modified since the plan, a symbolic or hard link, a special file, empty, binary, in UTF-16/32 or in an encoding not compatible with ASCII, carries a PWS draft banner or template syntax, or carries the Pine code of a closed source towards a public destination, the entire export waits, with the resolution (never an incomplete set). A declared document that has become unavailable gives a warning (`LICENSE_DOCUMENT_UNAVAILABLE`), never a block of routine work. The recorded SPDX identifier names the licence; it does not say by itself which documents and notices a redistribution requires.
  - An existing script that the holder prefers to place under a profile (relicensing, if they hold all the rights — evidence to be recorded) follows the profile path; a licence is never changed automatically.
- **Identity and year**: the copyright holder (`COPYRIGHT_HOLDER`) comes from the configuration (`pws.config.json`); the creation year from `license.created_year` (kept during updates). An **unknown year is never replaced by the current year**: the rendered header keeps `{{YEAR_RANGE}}` and remains a draft until `license confirm --created-year`; on the explicit creation of a new project, `pine-new` proposes the current year; a migration never fills in the year. The PWS distribution never imposes its authors as holder of your scripts.
- **Templates**: deliberately minimal format — `{{FIELD}}`, optional blocks `[[?FIELD:…]]` (kept if the field has a value) and `[[!FIELD:…]]` (kept if it is empty), `pws-template` provenance line removed at rendering. A rendered document declared final contains no residual template syntax; a malformed template produces an error, never a document. You may reuse, modify and distribute the rendered texts in your documents without PWS attribution (`TEMPLATE_PERMISSION.md`). The common template text remains PWS's; your additions and the content specific to your product are yours.
- **Original creation**: studying a legally accessible script serves to understand and compare; the implementation remains original (neither a copy, nor a line-by-line translation, nor a mere renaming). The references studied are traced in the design tracking, not as automatic credits in the script; an existing legitimate notice is never removed retroactively.
- **Legacy manifests**: schema 1 (`distribution`) and schema 2 (`license.publication` as a single string) are read and flagged; `migrate --apply` writes schema 3 keeping only what was **recorded**: the identifiable mode of a former value (`tradingview-open|protected|invite-only`), the private privacy of `tradingview-private`, the state of `unpublished`; everything else (state, privacy of the three modes, mode of a private value, the whole publication of a schema 1) remains null and appears among the points to confirm. Profile defaults are **proposals** (`license status` → `publication_proposed_by_profile`), never historical facts; the mentions observed in the source header (© year, "invite-only") are reported as references to confirm (`header_hints`), never written. The manifests migrated by the 2026-11-06 version that had received an inferred privacy are rectified by `m006` (traceable, idempotent); a value confirmed by `license confirm` is never called into question. No real setting is changed on TradingView.

## Commands

Guided path (menu `/pws → Qualité / publication → Licence et conditions d'utilisation`, in English "Quality / publication → Licence and terms of use"; skill `pine-license`): independent of publication preparation; it serves the four profiles without imposing an EULA on everyone (FREE with public source: CC header; FREE with closed source: free-use grant; PRIVATE: proprietary notice and optional particular permission; COMMERCIAL: configurable EULA) and keeps the existing licence of an imported script without imposing any document on it. It views (`overview`), completes in consistent groups with a summary and grouped confirmation (`set-fields`), previews (`preview`) and generates on explicit choice (`write`, then `confirm --terms-ref` to attach the document). The copyright holder (configuration) remains distinct from the legal identity of the provider (`PROVIDER_LEGAL_NAME`). A complete document is technically complete; it is not a legally validated contract.

```bash
python3 -m tools.pws_workspace license overview --slug <slug>            # consolidated state (read-only)
python3 -m tools.pws_workspace license status --slug <slug>
python3 -m tools.pws_workspace license preview --slug <slug> --kind header-free|header-proprietary|notice|grant|eula   # preview, nothing written
python3 -m tools.pws_workspace license set-fields --slug <slug> --field PROVIDER_LEGAL_NAME="…" [--clear NAME] [--dry-run]
python3 -m tools.pws_workspace license write  --slug <slug> --kind eula [--dest release/<name>.md]   # → release/EULA.md (DRAFT banner as long as fields are missing)
python3 -m tools.pws_workspace license confirm --slug <slug> --terms-ref release/EULA.md [--created-year …] [--state …] [--privacy …] [--mode …] [--terms-url https://…]   # --terms-ref: current and complete rendering only
python3 -m tools.pws_workspace license confirm --slug <slug> --clear created_year|state|privacy|mode|terms_ref|terms_url|license_id|license_documents   # resets a confirmed value to "unknown" (repeatable)
python3 -m tools.pws_workspace license fields-skeleton > scripts/<slug>/release/eula-fields.json
python3 -m tools.pws_workspace license detect --source "scripts/<slug>/<file>.pine"   # licence proposal read from the header (onboarding, read-only)
python3 -m tools.pws_workspace license confirm --slug <slug> --license-id MPL-2.0      # imported licence: exact identifier confirmed by the holder (closed list)
python3 -m tools.pws_workspace license confirm --slug <slug> --license-document LICENSE --license-document NOTICE   # imported licence: original legal documents declared (or --no-license-documents)
```
